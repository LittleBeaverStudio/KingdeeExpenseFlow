## 一、金额与发票的一致性口径（**通用 —— 与实现绑定，请勿改**）

这四条不是制度，是本 skill 的闸门行为，任何公司都适用：

1. **发票 < 报销** → 按发票金额**调低**报销额（`expense_edit.py fit`），这是正常下调，不是"越狱"。
2. **发票 > 报销** → 按**实际付款额**报，发票只作佐证；同时排查是否"多开"。
3. **发票还没进收票池** → 让员工在报销软件 / 发票云里把这张票**上传一次**（当天进池、当天拿到流水号）。
4. **提交闸门**（收票 0 行 / 无发票云流水号 / 跨组织 / 发票合计 < 报销额）**硬拦，没有任何绕过参数**。
   业务上确实要按原额报，唯一合法动作是**回费用申请单加额度**，不能在提交环节关校验。

## 二、行程单 vs 发票（**通用 —— 技术性防双算，请勿改**）

- 行程单（机票/火车票行程单、住宿清单）**一律传附件**，不传收票信息。
- 若把行程单传到收票信息 → 系统会把它也识别成金额，与发票**重复计入**，汇总金额虚高，易被财务驳回。
- 用户坚持 → 计算并展示**汇总金额**，标注风险，记录操作。

## 三、发票通用要求（**部分留位**）

- 购方抬头须 = **申请报销的组织全称**，税号须与该组织匹配。
  - 本组织名称 / 税号：**【待填】**
  - 抬头不符 → 拦截："发票购方为 {X}，与组织 {Y} 不一致，请重开或更换发票。"
- 发票须清晰、完整、未涂改；模糊/缺角 → 打回重拍。
- 是否接受电子发票 PDF / 数电票、是否要求验真截图：**【待填】**

## 六、提醒话术模板（**通用部分**）

| 场景 | 提醒 |
|---|---|
| **发票金额 < 报销金额** | "本单报销 {报销}，发票价税合计只有 {发票}，差额 {差}。**按发票金额报销**是允许的 —— 我把报销额调到 {发票} 再提交，可以吗？"（用 `expense_edit.py fit`；**没有**绕过参数，直接按原额提交会被闸门硬拦） |
| **发票还没进收票池** | "这张票还没进系统的收票池（没有发票云流水号）。**请先在报销软件 / 发票云里把这张票上传一次**，池里当天就有票、拿到流水号；在票进池之前，本单**提交会被硬闸门拦住**。" |
| 发票抬头不符 | "发票购方 {X} ≠ 组织 {Y}，请重开。" |
| 行程单误传收票信息 | "行程单请传附件，避免与发票重复计入被驳回。" |
| **制度项未登记** | "贵司制度里「{费用类型}」的要求还没登记（`policy_rules.local.md` 为空位），我按票面金额处理，请确认。" |
